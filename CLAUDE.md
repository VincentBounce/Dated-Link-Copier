# Dated Link Copier

Chrome MV3 extension: one click copies a dated reference line for the current page. Everything is in `background.js`: on click it injects self-contained functions with `chrome.scripting.executeScript` (permissions: scripting, activeTab, clipboardWrite, declarativeContent, offscreen; one host permission, chrome-stats.com, for Android and Chrome extension release dates). The line is copied by `writeClipboard()` through an offscreen document (`offscreen.html` + `offscreen.js`, execCommand on a textarea), so it also works on Chrome Web Store pages, where Chrome blocks extension scripts.

Date read (the user's convention, always): a page with no date of its own gets the month it was read, in parentheses, `(2026-10) <link>`, so it shows at once that it is not the page's date and not to the day; `consultedDate()` writes it. `xx` (`2021-10-xx`) is only for a page's own date whose day is unknown.

## Output formats (`?` when the date is missing on YouTube / Google Play / App Store / Chrome Web Store / Edge Add-ons / Firefox Add-ons / Steam / Meta Quest / Microsoft Store / Flathub / Chrome-Stats / Reddit / Hacker News / PubMed / arXiv / Amazon / SoundCloud / Pouët / Suno / Shadertoy / iCloud shortcuts / Medium publications / Printables / GitHub releases / Crunchbase / PyPI / Have I Been Pwned / Y Combinator / ScienceDirect Topics / Sony / NIDCD)

- YouTube video: `YYYY-MM-DD @Channel1 @Channel2 - Title [ID] https://youtu.be/ID` (`[ID]`, the user's format). Data comes from the player (`#movie_player.getPlayerResponse()`, MAIN world), checked against the video ID in the URL; collaborators come from the owner block's "Collaborators" dialog data. In channels and title, ` - ` becomes `, ` and `\ / : * ? " > < |` become `＼／：＊？＂＞＜｜`.
- YouTube channel (`/@handle`, `/channel/UC…`, `/c/…`, `/user/…`, with their tabs; `YOUTUBE_CHANNEL` rule): `YYYY-MM-DD https://www.youtube.com/@handle` (canonical link). The date joined ("Joined Mar 21, 2008", in the page's language: "Actif depuis le 21 mars 2008") is only in the About panel: `readYouTubeChannelInfo()` fetches `/<channel>/about` (~0.7 s, 2-3 MB) and reads `"joinedDateText":{"content":…}` and the `"canonicalChannelUrl"` after it, plus `<html lang>`; `localizedDate()` parses it. Some channels show no date (@YouTube): `?`. YouTube shows a consent page to new browsers (built-in browser: "Reject all"); curl works with `-H "Cookie: SOCS=CAI"`.
- Google Play app: `Android YYYY-MM-DD https://play.google.com/store/apps/details?id=…`. Release date = timestamp at `app[10][1][0]` of the AF_initDataCallback block whose `[1][2][77][0]` is the app id (key `ds:5` when signed out, another key when signed in). Read from the loaded page first (instant); when it has none (some apps have no date in any region, e.g. com.anthropic.aibo; or stale page after in-page navigation), `chromeStatsDate()` fetches `chrome-stats.com/d/<id>` from the service worker (~0.2 s; host permission, since the site sends no CORS header; regex on its JSON-LD `datePublished`, which can be a day before Google Play's UTC date), and last the app page is fetched for regions US, then FR, GB, CH (~1 s each, `readPlayAppInfo(true)`).
- App Store app (`apps.apple.com/<country>/app/<name>/id<id>`): `macOS-iOS-iPadOS-tvOS-watchOS-visionOS YYYY-MM-DD https://apps.apple.com/<country>/app/<name>/id<id>`, only the compatible platforms, in that order (the user's format). Platforms = `buttonAction.purchaseConfiguration.appPlatforms` (phone, pad, mac, tv, watch, vision) of `data[0].data.lockup` in the page's `#serialized-server-data` JSON, checked on `adamId` (stale after in-page navigation: then the app page is fetched), plus `(macOS)` when `lockup.isIOSBinaryMacOSCompatible` and `(visionOS)` when `supportsVisionOSCompatibleIOSBinary` without being native (iPhone/iPad app running there: parentheses, the user's format, `(macOS)-iPadOS` for Golly). The page shows no date: first release = `releaseDate` date part of `itunes.apple.com/lookup?id=<id>&country=<country>` (CORS allows apps.apple.com). The lookup's `supportedDevices` miss tvOS and visionOS, hence the page data. apps.apple.com fetches fine with curl.
- Chrome Web Store extension (`chromewebstore.google.com/detail/<slug>/<id>`): `Chrome ext YYYY-MM-DD https://chromewebstore.google.com/detail/<slug>/<id>` (the user's format). The Store shows only "Updated"; its page data has the first publication time (Unix seconds at `[0][17][0]` of the `ds:0` AF_initDataCallback block, `[0][0]` = id; Copy Clean Link: 2021-06-01 06:34 UTC), but Chrome blocks extensions from Store pages and from fetching them (even with a host permission: "Failed to fetch"). So the date is `chromeStatsDate(<id>)`: a US date (2021-05-31 there), and Chrome-Stats has no item before about 2020 (Google Translate: 2020-03-17 instead of 2009-12-03).
- Edge Add-ons (`microsoftedge.microsoft.com/addons/detail/<slug>/<id>`): `Edge ext YYYY-MM-DD <link>`, same branch as the Chrome Web Store: Chrome-Stats follows Edge items under the same `/d/<id>` (JSON-LD `operatingSystem: Edge`), with the same limit (no item before about 2022 there: uBlock Origin 2022-02-10). Edge's own API (`/addons/getproductdetailsbycrxid/<id>`) only has `lastUpdateDate`.
- Firefox Add-ons (`addons.mozilla.org/<lang>/firefox/addon/<slug>/`, also `/android/`): `Firefox ext YYYY-MM-DD https://addons.mozilla.org/firefox/addon/<slug>/` (`Firefox theme` for themes), `created` of the public API `addons.mozilla.org/api/v5/addons/addon/<slug>/` (CORS allowed), UTC date (`firefoxAddonLine()`).
- Steam game (`store.steampowered.com/app/<id>`): `Windows-macOS-Linux YYYY-MM-DD <canonical link>`, only the supported platforms, like the App Store. `readSteamAppInfo()` reads the same-site API `/api/appdetails?appids=<id>&l=english` (`release_date.date` "19 Apr, 2011", parsed by `localizedDate(…, "en")`; "Coming soon" texts give `?`; the day can differ by region: 18 from curl, 19 in the browser) and `platforms`.
- Meta Quest Store app (`www.meta.com/<locale>/experiences/<slug>/<id>/`): `Meta Quest YYYY-MM-DD https://www.meta.com/experiences/<slug>/<id>/`. `"release_info":{"display_date":"21 May 2019"}` (page language, `localizedDate()`) within 3000 chars after the app's `"id":"<id>"` in the loaded page; a fetched page is an empty shell (210 KB) and in-page navigation doesn't bring that data: `?` until the page is reloaded. curl gets a 400.
- Microsoft Store app or game (`apps.microsoft.com/detail/<id>`, 12 characters, or 14 for `XP…` Win32 products): `Windows (UWP|Win32) YYYY-MM-DD https://apps.microsoft.com/detail/<id>` (the user's format). Date = `"releaseDateUtc"` of the page data (once per page), accepted when the page has `"productId":"<id>"` (either case: lower or upper depending on the product); else the product page is fetched (in-page navigation; Microsoft answers 403 to quick repeated fetches). UTC date. `XP…` products (VLC) have no release date: `?`. Type: `Win32` when the page's `"installer":{"type":"WPM"}` (an .exe or .msi the Store downloads), else from the public catalog `displaycatalog.mp.microsoft.com/v7.0/products?bigIds=<ID>&market=US&languages=en-US` (CORS allows apps.microsoft.com): a package with the `runFullTrust` capability is Win32 in MSIX (Firefox, Spotify), without it UWP (Remote Desktop, OneNote for Windows 10); no package, no type.
- Flathub app (`flathub.org/<lang>/apps/<id>`): `Linux YYYY-MM-DD https://flathub.org/apps/<id>`, `added_at` (Unix seconds, UTC date) of the hit for that id in the same-site search API (POST `/api/v2/search` `{"query": id, "filters": []}`), read from the page: the API refuses the service worker's POST. It equals the creation of the app's `flathub/<id>` GitHub repository (Spotify, GIMP, Steam); Firefox, published directly by Mozilla, says 2023-07-11.
- Snapcraft is not supported: its page and API (`api.snapcraft.io/v2/snaps/info/<name>`, needs `Snap-Device-Series: 16`, no CORS) only give the current revisions. Google Play Games titles are Google Play `details?id=` pages, already handled.
- Chrome-Stats page (`chrome-stats.com/d/<id>`, Android apps and browser extensions): `YYYY-MM-DD https://chrome-stats.com/d/<id>`, no title (the user's choice). Date = `datePublished` of the JSON-LD SoftwareApplication whose `url` is the page's link (the head stays from the first page after in-page navigation, which gave the homepage link and title before: then the page is fetched, ~40 ms). Other pages fall through to the generic reader. Cloudflare blocks curl and headless Chrome (403 challenge), but not a real Chrome, even for the extension's cookieless background requests.
- Reddit post: `YYYY-MM-DD https://www.reddit.com/r/<sub>/comments/<id>/<slug>/`. Date = `created-timestamp` of `shreddit-post[id="t3_<id>"]` (new Reddit) or `data-timestamp` of `.thing[data-fullname="t3_<id>"]` (old Reddit), else JSON-LD `datePublished`, shown as the local date like Reddit does. Comment permalinks give the post link. Subreddit (`/r/<sub>/`, sort tabs too): `YYYY-MM-DD https://www.reddit.com/r/<sub>/`, creation date = `ts` of the `faceplate-timeago` in the `[slot="community-details"]` of `shreddit-subreddit-header[name="<sub>" i]` ("Created Jan 25, 2008"), or old Reddit's `.side .titlebox .age time[datetime]`; same reader (`readRedditInfo`) and local date as posts. reddit.com blocks curl with a bot check; test in a real browser.
- X (Twitter) post (`x.com` / `twitter.com`, `/<user>/status/<id>`): `YYYY-MM-DD https://x.com/<user>/status/<id>`, computed in the service worker without page access: snowflake ID, `(id >> 22) + 1288834974657` ms (BigInt), shown as the local date; `?` for pre-November-2010 IDs (< 1e13).
- X profile (`x.com/<user>`): `YYYY-MM-xx https://x.com/<user>`, month joined from the "Joined October 2021" line (`[data-testid="UserJoinDate"]` signed in, the parent of `svg[data-icon="icon-calendar"]` signed out), month names in the page's language through `Intl.DateTimeFormat`; the title "Name (@user) / X" must name the profile (in-page navigation). Nothing copied on other X pages (/home, /explore…), although their icon is colored. The page gives the text and `<html lang>`; the service worker's `localizedDate(text, lang)` (shared with YouTube channels) finds the year, the month name (Intl long and short names in that language, the longest found), the day if any (`xx` otherwise), also year-first ("2008年3月21日", "2008. 3. 21.") and day-first numeric ("21.03.2008") dates.
- TikTok video, Instagram post/reel, Threads post, Bluesky post: `YYYY-MM-DD <link>`, computed by `idPostLine()` without page access, local date (checked on 1 to 3 real posts each): TikTok `/@user/video/<id>` (or `/photo/`), `id >> 32` = Unix seconds, link `https://www.tiktok.com/@user/video/<id>`; Instagram `/p/<code>/`, `/reel(s)/<code>/`, `/tv/`, also under `/<user>/`, and Threads `/@user/post/<code>` (threads.com or .net): the code is the media ID in base 64 (`A-Z a-z 0-9 - _`), `(id >> 23) + 1314220021721` ms, `?` for pre-sharding IDs (< 2^40), links `https://www.instagram.com/<p|reel|tv>/<code>/` (Instagram: `YYYY-MM-DD @<user> <link>`, the user's format, since `/p/<code>/` links don't name the creator: the `/<user>/p/` segment when present, else `readInstagramUser(code)` reads `og:url` "https://www.instagram.com/<user>/reel/<code>/" of the loaded page when it names that code, else of the fetched `/p/<code>/` page, ~0.5 s, after in-page navigation) and `https://www.threads.com/@user/post/<code>`; Bluesky `bsky.app/profile/<handle>/post/<rkey>`: the rkey is a TID, 13 base-32 digits (`2-7 a-z`), value >> 10 = microseconds. Checks: TikTok page `createTime`, Instagram `og:description` "on October 29, 2026", Threads `time[datetime]`, Bluesky public API `getAuthorFeed` `createdAt`.
- Mastodon post on any server (`<server>/@user/<id>`, also `/@user@server/<id>`, 6-19 digits): `YYYY-MM-DD https://<server>/@user/<id>`, in `idPostLine()`: `id >> 16` = ms, local date; `?` for the first sequential IDs (< 2^40). Checked against the API's `created_at` (mastodon.social `/api/v1/accounts/<id>/statuses`).
- GitHub repository (`github.com/<owner>/<repo>`, root only), issue, pull request (`/issues/<n>`, `/pull/<n>`, with subpaths), commit (`/commit/<sha>`), and the same on GitLab (`gitlab.com/<group>/…/<project>`, `/-/issues/<n>`, `/-/merge_requests/<n>`, `/-/commit/<sha>`; API `gitlab.com/api/v4/projects/<url-encoded path>`, `created_at`, `title`, `repository/commits/<sha>` `committed_date`): `forgeLine()` with one entry per forge in `FORGES`, in the service worker; GitHub REST API `api.github.com/repos/<owner>/<repo>` (`created_at`, or the first commit's `commit.committer.date` when older: last page of `/commits?per_page=1`, from its `Link` header, two requests more; the user's choice, since commit dates are the author's own: voice-workshop created 2026-11-08, first commit 2026-10-21; torvalds/linux 2005-04-17; GitLab keeps `created_at`), `/issues/<n>` or `/pulls/<n>` (`created_at`, `title`; pulls has its own endpoint, since repos with issues disabled answer 410 to /issues, e.g. torvalds/linux), `/commits/<sha>` (`commit.committer.date`, message's first line); local date; titles through `titleIfNotInLink`. CORS allowed, 60 requests an hour without sign-in; any failure or other page (users, /features/…) returns null, then the generic reader.
- Wikipedia article (`<lang>.wikipedia.org/wiki/<title>`, mobile `.m.` too): `YYYY-MM-DD https://<lang>.wikipedia.org/wiki/<title>`, creation date = first revision (`api.php?action=query&prop=revisions&rvdir=newer&rvlimit=1&redirects=1&origin=*`), UTC date as shown to signed-out readers; a redirect (/wiki/UK) gives its target's creation.
- npm package (`www.npmjs.com/package/<name>`, scoped too): `YYYY-MM-DD https://www.npmjs.com/package/<name>`, first release = `time.created` of `registry.npmjs.org/<name>` (scope slash as %2F; CORS allowed; full document, 16 MB for typescript, ~0.3 s), UTC date like PyPI.
- LinkedIn post (`/posts/…-share-ID-…`, `…-activity-ID-…`, `/feed/update/urn:li:activity:ID`): `YYYY-MM-DD https://www.linkedin.com<path without query>`, computed without page access: the 19-digit activity/share/ugcPost ID >> 22 = creation time in ms (BigInt), local date. Checked against the public page's JSON-LD `datePublished`. Pulse articles fall through to the generic reader.
- LinkedIn company page (`/company/<slug>`, `/about/` and other tabs): `YYYY-xx-xx https://www.linkedin.com/company/<slug>/about/` (the user's format: the same line on every tab, with the About tab's link, which shows the year), founding year = the only `dd` whose text is a bare year (`readLinkedInFoundedYear(about)`): signed out, `<div data-test-id="about-us__foundedOn"><dt>Founded</dt><dd>2024</dd>` on the company page (checked in a real signed-out Chrome: interencheres 2000; curl now gets 403, and a cookieless fetch gets 999); signed in, only the /about/ tab has it (label in the UI language), so on other tabs /about/ is fetched with the session: its dd list, else `"foundedOn":{…"year":2000}` of its page data (untested: no signed-in session here). `?` when no year is found. The `LINKEDIN_PAGE` icon rule covers posts, Pulse and company pages.
- Facebook page or profile (`www.facebook.com/<name>` or `/profile.php?id=<id>`, with its tabs; not posts, photos, videos, nor Facebook's own sections): `YYYY-MM-DD https://www.facebook.com/<name>`, no title ("(6) Facebook" signed in, "Relay | Facebook" signed out), creation date = the `"text":"March 10, 2020"},"field_type":"creation_date"` of the Page transparency tab (`/<name>/about_profile_transparency`, `profile.php?id=<id>&sk=about_profile_transparency`), shown signed out too, in the page's language (`localizedDate()`); only the signed-out layout has Page transparency (signed in, About shows Intro, Category, Details, Links, Contact info, and the fetched tab is 2 MB without the field), so `readFacebookPageCreated()` reads the loaded page when it is that tab signed out, else fetches it without cookies (`credentials: "omit"`) and with `Accept: text/html` (without it the answer is a 0.5 MB shell without the field; with it 15 MB, 1.5-4 s), language from the fetched `<html lang>`. Profiles have it too (zuck 2004-02-11; Meta 2020-01-31, its current page). No date: the date read. Checked in the user's Brave through Claude in Chrome, signed out and signed in: relayfinancial 2020-03-10.
- Instagram profile (`www.instagram.com/<user>/`): `YYYY-MM-xx https://www.instagram.com/<user>` (no final slash, the user's choice, like Facebook), month joined of "About this account" (signed in only: "Date joined", "April 2022"), else `(YYYY-MM)`, the date read; no title ("Relay (@relayfinancial) • Instagram photos and videos"). `readInstagramJoined(user)` fetches `/<user>/` (~0.4 s; account ID `"profilePage_<id>"`, tokens `"DTSGInitialData",[],{"token":…}`, `"LSD"`, `"WebBloksVersioningID",[],{"versioningID":…}`; the loaded page keeps the first profile after in-page navigation), then POSTs the sheet's Bloks request `/async/wbloks/fetch/?appid=com.bloks.www.ig.about_this_account&type=app&__bkv=<versioningID>` (form `__a=1`, `fb_dtsg`, `lsd`, `params={"referer_type":"ProfileUsername","target_user_id":<id>}`; without `__bkv`: 500) and returns its texts `")":"…"` in the UI language; the first that `localizedDate()` reads is the month joined (later ones: "Verified" "June 2016"). Signed out, no tokens (and `web_profile_info` answers 401 or 404): the date read. Checked in the user's Brave, signed in: relayfinancial 2022-04, instagram 2012-02, zuck 2010-10, interencheres 2015-06.
- Amazon product (`www.amazon.{com,ca,co.uk,fr,de,es,it}`, `/dp/<ASIN>` or `/gp/product/<ASIN>`): `YYYY-MM-DD https://www.amazon.<tld><lang segment and product name>/dp/<the page's ASIN>/` (no query; Amazon ignores the name): the canonical link's name; when the canonical link names another ASIN (a variant's parent: `/-/en/TONGOU/dp/B0GFM6WJRJ` on B0B7MYYT2V), the page's own name if its path has one (`/-/en/Connected-16A-…/dp/B0B7MYYT2V`), else the parent's (`/-/en/dp/B0D5D4LZDN` → `/-/en/TONGOU-SY1-WIFI-Smart-Switch/dp/B0D5D4LZDN`). Date = "Date First Available" row of the product details (`#prodDetails tr`, `#detailBullets_feature_div li`…), labels and month names in English, French, German, Spanish, Italian; many products have no such row, then the oldest `[data-hook="review-date"]` shown on the page ("Reviewed in the United States on February 9, 2026"), then `?`. Then ` (YYYY-MM) <price>` (the user's format): month read and buy-box price from the hidden fields `items[0.base][customerVisiblePrice][amount|currencyCode]` (first offer; checked on `items[0.base][asin]`), only in the site's own currency, known from the host (USD, CAD, GBP, else EUR; the user's choice: never converted): Amazon converts to the visitor's currency preference (cookie `i18n-prefs`, EUR on amazon.co.uk from France; no URL parameter changes it) and the page then has no original price, so no suffix, written by `priceText()`: `Intl` English currency symbol (`€39.99`, `CA$`), else a single Unicode currency sign (`₺`), else the code (`AED39.99`); no suffix without a price. amazon.com product pages can be fetched with curl and a browser user agent.
- Hacker News item (`news.ycombinator.com/item?id=…`): `YYYY-MM-DD <story title> https://news.ycombinator.com/item?id=<id>`. - PubMed (`pubmed.ncbi.nlm.nih.gov/<PMID>/`): `YYYY-MM-DD <title> https://pubmed.ncbi.nlm.nih.gov/<PMID>/`. No date metadata: "Epub 2020 Dec 10." in the first `.secondary-date`, else the issue date before ";" in `.article-citation .cit`; missing day or month become `xx`. Title = `citation_title` without the final period, through `titleIfNotInLink`. PubMed shows a reCAPTCHA to automated browsers: check data with the NCBI E-utilities (`eutils.ncbi.nlm.nih.gov/entrez/eutils/esummary.fcgi?db=pubmed&id=<PMID>&retmode=json`) and the page layout through the Wayback Machine.
- arXiv paper (`arxiv.org/abs|pdf|html/<id>`, `ar5iv.arxiv.org/html/<id>` or `ar5iv.labs.arxiv.org`, versions `v5` and old ids `math/0211159` too): `YYYY-MM-DD <title> <link>`, computed by `arxivLine()` in the service worker without page access. Date = "Submitted" v1 of the paper's DOI record at DataCite (`api.datacite.org/dois/10.48550/arxiv.<id>`, CORS allowed; UTC date, equal to the abstract page's `citation_date` on papers from 2002 to two days old; `citation_online_date` is the last version's: 2023-08-02 for 1706.03762 instead of 2017-06-12), else the ID's month (`1804` → `2018-04-xx`). Title = DataCite `titles[0]`, its TeX math in Unicode by `unicodeMath()` (`$a^3b^2$` → `a³b²`, Greek letters, `\mathbb{R}` → `ℝ`; a character without a Unicode superscript or subscript keeps `^`/`_`, other commands their name), through `titleIfNotInLink`. Link: an HTML version (arxiv.org or ar5iv) gives the PDF link `https://arxiv.org/pdf/<id><version>` (the user's choice), the abstract page and the PDF keep theirs. arxiv.org sends no CORS header (nor does `export.arxiv.org/api`), and ar5iv pages have a title but no date; Chrome's PDF viewer document only has the PDF's own title ("THE REST OF … REGULAR\nPOLYGONS").

## Clean Link shortcut

`shortcut/Clean Link.shortcut` (iOS, iPadOS, macOS Shortcuts) cleans the links of the clipboard text, without dates: Get Clipboard → Text (a link copied on iOS is a URL item, which Base64 Encode would download: the page's HTML, 2.30.1) → Base64 → a page running `shortcut/clean-link.js` (Get Contents of Web Page on a base64 `data:text/html` URL, the only JavaScript runtime of Shortcuts; trick seen in Detrackor) → trailing spaces trimmed → Set Clipboard → notification. Get Contents of Web Page must get its URL as a text token (`WFTextTokenString`, as in Detrackor); as a plain attachment it returns nothing and the clipboard stays unchanged (2.30.0). Test the real shortcut on the Mac: `pbcopy` a link (or put a URL item with JXA `NSPasteboard.writeObjects([NSURL])`, like iOS), `shortcuts run "Clean Link"`, `LANG=en_US.UTF-8 pbpaste`. `cleanLink()`: X posts → `https://x.com/<user>/status/<id>`, YouTube (watch, Shorts, youtu.be) → `https://youtu.be/<id>` keeping `t`, Google Play → `?id=` only, Amazon → `/dp/<ASIN>`, Reddit and LinkedIn posts → path without query; other links lose the tracking parameters only (other parameters and fragment kept, unchanged when nothing is removed); then `readableLinks()`. `python3 tools/make_shortcut.py [--js out.js]` copies the `tracking` regex and `readableLinks()` from `background.js` into the script (one list), writes the plist and signs it with `shortcuts sign --mode anyone`; rebuild it when they change. Test: `--js` gives the assembled script; headless Chrome `--dump-dom "data:text/html;base64,…"` runs the page as the shortcut does.

## Icon

`icons/icon.svg` (blue rounded square, white calendar, blue chain link) with 16/32/48/128 px PNGs, plus grey 16/32 px copies (`icons/icon-disabled-*.png`) used as the toolbar default. Chrome draws a disabled action grey only on pages the extension can't access, and activeTab makes every web page accessible, so `chrome.action.disable()` alone never greys the icon on http(s) pages. Hence: default icon = grey copy, and a declarativeContent rule (ShowAction + SetIcon with the colored image data) on YouTube videos/Shorts and channels, Google Play app pages, Reddit posts and subreddits, X posts and profiles, LinkedIn posts, company pages and Pulse articles, Amazon products, and any other site (`anyHostExcept()` builds a lookahead-free regex, since rules can't exclude hosts).
