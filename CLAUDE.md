# Dated Link Copier

Chrome MV3 extension: one click copies a dated reference line for the current page. Everything is in `background.js`: on click it injects self-contained functions with `chrome.scripting.executeScript` (permissions: scripting, activeTab, clipboardWrite, declarativeContent, offscreen; one host permission, chrome-stats.com, for Android and Chrome extension release dates). The line is copied by `writeClipboard()` through an offscreen document (`offscreen.html` + `offscreen.js`, execCommand on a textarea), so it also works on Chrome Web Store pages, where Chrome blocks extension scripts.

Date read (the user's convention, always): a page with no date of its own gets the month it was read, in parentheses, `(2026-10) <link>`, so it shows at once that it is not the page's date and not to the day; `consultedDate()` writes it. `xx` (`2021-10-xx`) is only for a page's own date whose day is unknown.

- YouTube video: `YYYY-MM-DD @Channel1 @Channel2 - Title https://youtu.be/ID`. Data comes from the player (`#movie_player.getPlayerResponse()`, MAIN world), checked against the video ID in the URL; collaborators come from the owner block's "Collaborators" dialog data. In channels and title, ` - ` becomes `, ` and `\ / : * ? " > < |` become `＼／：＊？＂＞＜｜`.
- YouTube channel (`/@handle`, `/channel/UC…`, `/c/…`, `/user/…`, with their tabs; `YOUTUBE_CHANNEL` rule): `YYYY-MM-DD https://www.youtube.com/@handle` (canonical link). The date joined ("Joined Mar 21, 2008", in the page's language: "Actif depuis le 21 mars 2008") is only in the About panel: `readYouTubeChannelInfo()` fetches `/<channel>/about` (~0.7 s, 2-3 MB) and reads `"joinedDateText":{"content":…}` and the `"canonicalChannelUrl"` after it, plus `<html lang>`; `localizedDate()` parses it. Some channels show no date (@YouTube): `?`. YouTube shows a consent page to new browsers (built-in browser: "Reject all"); curl works with `-H "Cookie: SOCS=CAI"`.
- Google Play app: `Android YYYY-MM-DD https://play.google.com/store/apps/details?id=…`. Release date = timestamp at `app[10][1][0]` of the AF_initDataCallback block whose `[1][2][77][0]` is the app id (key `ds:5` when signed out, another key when signed in). Read from the loaded page first (instant); when it has none (some apps have no date in any region, e.g. com.anthropic.aibo; or stale page after in-page navigation), `chromeStatsDate()` fetches `chrome-stats.com/d/<id>` from the service worker (~0.2 s; host permission, since the site sends no CORS header; regex on its JSON-LD `datePublished`, which can be a day before Google Play's UTC date), and last the app page is fetched for regions US, then FR, GB, CH (~1 s each, `readPlayAppInfo(true)`).
- App Store app (`apps.apple.com/<country>/app/<name>/id<id>`): `macOS-iOS-iPadOS-tvOS-watchOS-visionOS YYYY-MM-DD https://apps.apple.com/<country>/app/<name>/id<id>`, only the compatible platforms, in that order (the user's format). Platforms = `buttonAction.purchaseConfiguration.appPlatforms` (phone, pad, mac, tv, watch, vision) of `data[0].data.lockup` in the page's `#serialized-server-data` JSON, checked on `adamId` (stale after in-page navigation: then the app page is fetched), plus macOS when `lockup.isIOSBinaryMacOSCompatible` and visionOS when `supportsVisionOSCompatibleIOSBinary`. The page shows no date: first release = `releaseDate` date part of `itunes.apple.com/lookup?id=<id>&country=<country>` (CORS allows apps.apple.com). The lookup's `supportedDevices` miss tvOS and visionOS, hence the page data. apps.apple.com fetches fine with curl.
- Chrome Web Store extension (`chromewebstore.google.com/detail/<slug>/<id>`): `Chrome ext YYYY-MM-DD https://chromewebstore.google.com/detail/<slug>/<id>` (the user's format). The Store shows only "Updated"; its page data has the first publication time (Unix seconds at `[0][17][0]` of the `ds:0` AF_initDataCallback block, `[0][0]` = id; Copy Clean Link: 2021-06-01 06:34 UTC), but Chrome blocks extensions from Store pages and from fetching them (even with a host permission: "Failed to fetch"). So the date is `chromeStatsDate(<id>)`: a US date (2021-05-31 there), and Chrome-Stats has no item before about 2020 (Google Translate: 2020-03-17 instead of 2009-12-03).
- Edge Add-ons (`microsoftedge.microsoft.com/addons/detail/<slug>/<id>`): `Edge ext YYYY-MM-DD <link>`, same branch as the Chrome Web Store: Chrome-Stats follows Edge items under the same `/d/<id>` (JSON-LD `operatingSystem: Edge`), with the same limit (no item before about 2022 there: uBlock Origin 2022-02-10). Edge's own API (`/addons/getproductdetailsbycrxid/<id>`) only has `lastUpdateDate`.
- Firefox Add-ons (`addons.mozilla.org/<lang>/firefox/addon/<slug>/`, also `/android/`): `Firefox ext YYYY-MM-DD https://addons.mozilla.org/firefox/addon/<slug>/` (`Firefox theme` for themes), `created` of the public API `addons.mozilla.org/api/v5/addons/addon/<slug>/` (CORS allowed), UTC date (`firefoxAddonLine()`).
- Steam game (`store.steampowered.com/app/<id>`): `Windows-macOS-Linux YYYY-MM-DD <canonical link>`, only the supported platforms, like the App Store. `readSteamAppInfo()` reads the same-site API `/api/appdetails?appids=<id>&l=english` (`release_date.date` "19 Apr, 2011", parsed by `localizedDate(…, "en")`; "Coming soon" texts give `?`; the day can differ by region: 18 from curl, 19 in the browser) and `platforms`.

UTC date.
- Flathub app (`flathub.org/<lang>/apps/<id>`): `Linux YYYY-MM-DD https://flathub.org/apps/<id>`, `added_at` (Unix seconds, UTC date) of the hit for that id in the same-site search API (POST `/api/v2/search` `{"query": id, "filters": []}`), read from the page: the API refuses the service worker's POST. It equals the creation of the app's `flathub/<id>` GitHub repository (Spotify, GIMP, Steam); Firefox, published directly by Mozilla, says 2023-07-11.
- Snapcraft is not supported: its page and API (`api.snapcraft.io/v2/snaps/info/<name>`, needs `Snap-Device-Series: 16`, no CORS) only give the current revisions. Google Play Games titles are Google Play `details?id=` pages, already handled.
- Chrome-Stats page (`chrome-stats.com/d/<id>`, Android apps and browser extensions): `YYYY-MM-DD https://chrome-stats.com/d/<id>`, no title (the user's choice). - X (Twitter) post (`x.com` / `twitter.com`, `/<user>/status/<id>`): `YYYY-MM-DD https://x.com/<user>/status/<id>`, computed in the service worker without page access: snowflake ID, `(id >> 22) + 1288834974657` ms (BigInt), shown as the local date; `?` for pre-November-2010 IDs (< 1e13).
- X profile (`x.com/<user>`): `YYYY-MM-xx https://x.com/<user>`, month joined from the "Joined October 2021" line (`[data-testid="UserJoinDate"]` signed in, the parent of `svg[data-icon="icon-calendar"]` signed out), month names in the page's language through `Intl.DateTimeFormat`; the title "Name (@user) / X" must name the profile (in-page navigation). Nothing copied on other X pages (/home, /explore…), although their icon is colored. The page gives the text and `<html lang>`; the service worker's `localizedDate(text, lang)` (shared with YouTube channels) finds the year, the month name (Intl long and short names in that language, the longest found), the day if any (`xx` otherwise), also year-first ("2008年3月21日", "2008. 3. 21.") and day-first numeric ("21.03.2008") dates.

- Any other page: `YYYY-MM-DD <link>` (nothing copied and ✗ when no date is found) from the first complete date (`YYYY-MM-DD`, "2025/06/03" normalized) among `article:published_time`, `itemprop=datePublished`, `name=date`, `citation_online_date`, `dc.date`, `citation_publication_date` (can be the print issue month only, "2026/07") and JSON-LD `datePublished`, else `shownDate()`: the first `time[datetime]`, else the text after "Publié le" / "Published on" / "Veröffentlicht am" / "Pubblicato il" / "Publicado el"… ("14.11.2021" day first, except mm/dd/yyyy after an English label with slashes; "14 novembre 2021", "November 14, 2021"), e.g. auto-illustrierte.ch, else the text of `article .date` (or the first `.date`) without label, e.g. ameli.fr `<p class="date">12 août 2025</p>`; both texts parsed by `dateFromText()`; canonical link when on the same host, else the URL without the fragment and tracking parameters: prefixes `utm_`, `mtm_`, `matomo_`, `pk_`, `piwik_`, `hsa_`, and exact names (`fbclid`, `gclid`, `gclsrc`, `gbraid`, `wbraid`, `gad_source`, `srsltid`, `msclkid`, `igshid`, `igsh`, `ttclid`, `twclid`, `li_fat_id`, `yclid`, `mc_cid`, `mc_eid`, `_hsenc`, `_hsmi`, `mkt_tok`, `_ga`, `_ke`, `ef_id`, `s_kwcid`, `epik`), gathered from URL cleaners and ClearURLs; generic names (`ref`, `s`, `t`, `si`) are kept, as they carry meaning on many sites.

Links in every line go through `readableLinks()`: percent-encoded UTF-8 is decoded like the address bar shows it (`clean-link-—-copy-urls-wi`, `École_normale`), while ASCII escapes (`%20`, `%2F`, `%3F`…), spaces (`%C2%A0`, `%E3%80%80`) and control characters stay encoded.

Title in the line: for the generic reader and Sony, `titleIfNotInLink()` inserts the file-name-safe title (`cleanText`) between date and link when fewer than half of the title's words (4+ letters, accents removed) appear in the link's path, e.g. `2025-06-03 AI tutoring outperforms in-class active learning： an RCT … https://www.nature.com/articles/s41598-025-97652-6`. Title = `citation_title` / `dc.title` / `og:title` / `document.title`, minus a trailing " | <og:site_name>" and anything after a last " | ".

## Clean Link shortcut

`shortcut/Clean Link.shortcut` (iOS, iPadOS, macOS Shortcuts) cleans the links of the clipboard text, without dates: Get Clipboard → Text (a link copied on iOS is a URL item, which Base64 Encode would download: the page's HTML, 2.30.1) → Base64 → a page running `shortcut/clean-link.js` (Get Contents of Web Page on a base64 `data:text/html` URL, the only JavaScript runtime of Shortcuts; trick seen in Detrackor) → trailing spaces trimmed → Set Clipboard → notification. Get Contents of Web Page must get its URL as a text token (`WFTextTokenString`, as in Detrackor); as a plain attachment it returns nothing and the clipboard stays unchanged (2.30.0). Test the real shortcut on the Mac: `pbcopy` a link (or put a URL item with JXA `NSPasteboard.writeObjects([NSURL])`, like iOS), `shortcuts run "Clean Link"`, `LANG=en_US.UTF-8 pbpaste`. `cleanLink()`: X posts → `https://x.com/<user>/status/<id>`, YouTube (watch, Shorts, youtu.be) → `https://youtu.be/<id>` keeping `t`, Google Play → `?id=` only, Amazon → `/dp/<ASIN>`, Reddit and LinkedIn posts → path without query; other links lose the tracking parameters only (other parameters and fragment kept, unchanged when nothing is removed); then `readableLinks()`. `python3 tools/make_shortcut.py [--js out.js]` copies the `tracking` regex and `readableLinks()` from `background.js` into the script (one list), writes the plist and signs it with `shortcuts sign --mode anyone`; rebuild it when they change. Test: `--js` gives the assembled script; headless Chrome `--dump-dom "data:text/html;base64,…"` runs the page as the shortcut does.

## Icon

`icons/icon.svg` (blue rounded square, white calendar, blue chain link) with 16/32/48/128 px PNGs, plus grey 16/32 px copies (`icons/icon-disabled-*.png`) used as the toolbar default. Chrome draws a disabled action grey only on pages the extension can't access, and activeTab makes every web page accessible, so `chrome.action.disable()` alone never greys the icon on http(s) pages. Hence: default icon = grey copy, and a declarativeContent rule (ShowAction + SetIcon with the colored image data) on YouTube videos/Shorts and channels, Google Play app pages, Reddit posts and subreddits, X posts and profiles, LinkedIn posts (plus Pulse articles), Amazon products, and any other site (`anyHostExcept()` builds a lookahead-free regex, since rules can't exclude hosts).

- Don't ask questions: pick the sensible default, do it, say in one line what you chose.
- For each change: test it for real, commit to `main`, bump the SemVer version in `manifest.json` (patch = fix, minor = feature, major = big change), tag `vX.Y.Z`, push, and create the GitHub release with the zip: `git archive --format=zip --prefix=dated-link-copier-X.Y.Z/ -o dated-link-copier-X.Y.Z.zip vX.Y.Z manifest.json background.js icons/icon-16.png icons/icon-32.png icons/icon-48.png icons/icon-128.png icons/icon-disabled-16.png icons/icon-disabled-32.png offscreen.html offscreen.js`. Release notes end with `_Built with Claude Code (<model>)._`
- Update the README (formats and versions table) when behavior changes.
- Everything on GitHub (code, comments, commits, README, release notes) is English only. Talk to the owner in French.
- Version history: 0.1 vibe coded with Grok, 0.2–0.3 with Perplexity, 1.0 and later with Claude Code. The commits up to 1.1.0 are backdated imports of older folders.
